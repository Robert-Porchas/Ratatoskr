# Session diagnostics experiment

This experiment measures whether automatic sanitized session findings reduce **total Codex task tokens**, not merely browser response bytes. Ratatoskr runs its real MCP executor, observer, reducer and inspector. No model runs inside Ratatoskr.

## Reproduce

Normal prerequisites are the repository's supported Node/npm versions and installed dependencies. Chromium must be installed (`npm run setup`). Local browser/security tests need no account, API key or network service:

```sh
npm ci
npm run setup
npm run test:session
npm run test:benchmark
```

Native model tasks additionally require the Codex CLI, a logged-in account with access to the selected model, and connectivity to Codex. They consume account usage. An OpenAI API key is not required for this driver. No tokenizer or optional monitoring service is used.

```sh
# Small validation: three fresh tasks on the same missing-cookie scenario
BENCHMARK_MODEL=gpt-6.1-sol BENCHMARK_RUNS=1 \
BENCHMARK_SESSION_SCENARIOS=missing BENCHMARK_SUITE=session-check \
npm run benchmark:session

# Repeated suite: 120 fresh tasks; optional concurrency is at most two
BENCHMARK_MODEL=gpt-6.1-sol BENCHMARK_RUNS=10 \
BENCHMARK_CONCURRENCY=2 BENCHMARK_SUITE=session-comparison \
npm run benchmark:session

npm run benchmark:session:summary -- \
  benchmarks/browser-evidence/results/session-comparison/results.jsonl

# Re-audit every attempt against native tool events and actual fixture requests
npm run benchmark:session:audit -- \
  benchmarks/browser-evidence/results/session-comparison
```

Use a new suite name each time; the runner refuses to overwrite prior evidence. `BENCHMARK_SESSION_CASES=without,with` omits direct tasks. `BENCHMARK_CODEX_REASONING_EFFORT` defaults to `medium`. The complete task prompt/source contract is generated by [session-contract.ts](../session-contract.ts) and stored as `task.json` for every attempt. Its wording is identical across modes for a scenario; fixture implementation causes are not supplied as source facts.

## Cases and fixture

The [local fixture](../../../test/fixture/session.ts) uses fake cookie/storage values, real HTTP requests and a fresh browser context. Every task signs in, verifies acceptance, opens account details/settings, and verifies dashboard access. The scenarios are:

| Scenario    | Controlled behavior                                                    | Required diagnosis                            |
| ----------- | ---------------------------------------------------------------------- | --------------------------------------------- |
| `success`   | Cookie retained; protected request returns 200                         | Verified dashboard access                     |
| `missing`   | Login 200 sets an invalid-domain cookie; protected request returns 401 | Cookie not retained; `UNAUTHENTICATED`        |
| `loss`      | Sign-out deletes the cookie; next protected request returns 401        | Session removal and protected failure         |
| `scope`     | Cookie retained at `/restricted`; protected API is outside that path   | Cite the cookie path and protected failure    |
| `unrelated` | Authentication succeeds; a requested button is absent                  | Missing control, not an invented auth failure |

`without` sets `RATATOSKR_SESSION_DIAGNOSTICS=off`; `with` uses the production default. They share the observer, sanitized persistence, Level 2 inspection, schemas and browser state. This isolates automatic Level 1, **not** the runtime cost of adding the observer to old Ratatoskr.

`direct` uses pinned official `@playwright/mcp@0.0.83`: the existing safe core plus read-only cookie/localStorage/sessionStorage lists and individual request detail (21 tools). It uses native MCP observations; arbitrary evaluation, code execution and unrestricted file access are excluded. Default direct comparisons cover `missing` and `scope`. This is a clearly scoped Playwright MCP baseline, **not Codex's built-in browser tool or unrestricted code-capable automation**.

## Accounting and correctness

Each measured task starts in a new ephemeral Codex process/thread immediately before receiving its task and ends at its final structured diagnosis. Repository exploration, compilation and this development conversation are excluded. The runner fixes model/reasoning, viewport 1280×720, Chromium version, timeout 180 seconds and maximum 24 tool calls, and rotates case order across repetitions.

Token accounting is native **`turn.completed.usage`**, cumulative over the entire Codex task: `input_tokens`, `cached_input_tokens`, `output_tokens`, and `reasoning_output_tokens` when exposed. Total tokens are input plus output; cached input and reasoning output are subsets, not extra tokens. Non-cached input is input minus cached input. Missing fields stay unavailable. The CLI does not expose individual internal model-inference counts, so `modelCalls` is null. No transcript/byte-to-token estimate is substituted.

Terminal MCP events count every model-visible reply, including validation/transport errors. Browser evidence bytes retain their existing measurement; local session metadata bytes are a separate metric. Binary artifacts, canonical failure bytes and the serialized model-visible MCP representation are distinct measurements. Runtime capture/diff timings are not token counts.

`browserInteractions` counts attempted canonical steps plus initial navigation for Ratatoskr (including assertions), versus individual browser MCP calls for direct mode (including observations). Neither counts internal Playwright polling; session captures are reported separately. `rawEvidenceBytes` measures Ratatoskr's event log versus serialized direct MCP observations, not every byte in the browser or every auxiliary Playwright file. These supporting counters do not substitute for task-token accounting.

Grading verifies actual fixture requests, final HTTP/error diagnosis and evidence exposed to Codex. Merely completing a plan is insufficient. Unsupported claims that omitted header listings prove the server sent no Set-Cookie fail grading. All attempts—including failed diagnoses, retries and unnecessary inspections—remain in the statistics. Medians, mean, min/max and standard deviation describe tokens; success counts must accompany savings comparisons. A cheaper incomplete direct task is not equivalent diagnostic quality.

## Records and publication

Ignored `results/<suite>/` directories preserve every attempt, native JSONL events, usage, tool sequence, final report, fixture audit, and local run/artifacts. **Do not commit or publicly share raw logs or auth state.**

Counts-only publication verifies records against the native usage events before writing `results.jsonl`, `native-usage.jsonl`, `configuration.json`, `pre-change.json` and generated `summary.md` here. It omits tool bodies, browser artifacts and Codex thread IDs. Publish audited results; the original measurements remain unchanged in the ignored suite directory. If grading changed, publication also retains a whitelisted grading audit and the original summary. The publisher accepts current session results plus the preserved pre-change profile results:

```sh
npm run benchmark:session:publish -- \
  benchmarks/browser-evidence/results/session-comparison/audited-results.jsonl \
  benchmarks/browser-evidence/results/session-pre-cb13bf1/results.jsonl
```

The historical pre-change profile pair used Codex 0.160.0; this session experiment uses 0.160.1 and different tasks. It is a provenance baseline, not a causal before/after session-token comparison. The matched `without`/`with` controls are the primary session comparison. An initial development trial was nearly token-neutral and did not eliminate inspection; its direct diagnosis also made an unsupported header claim. It is not substituted for the repeated production series.

The final repeated series was executed at `5436d2c`. Its original grader required cookie inspection after response-body retrieval; that wrongly rejected inspection performed after a visible/HTTP failure but before retrieving the body. The corrected grader accepts either valid ordering, still rejects pre-login cookie observations and unsupported header claims, and rechecks **every** task without changing tokens, bytes or browser execution. The counts-only audit records both grades; the original summary remains available. Earlier archives keep their original scoring and are not mixed with the final contract.

`rawLocalSessionEvidenceBytes` counts sanitized metadata retained locally, not raw credential bytes. Optional state files and ordinary browser evidence have separate measurements. See the [generated summary](summary.md) and [sprint report](report.md) for measured outcomes and limitations. No universal token-saving claim follows from this fixture.
