# Ratatoskr architecture

This is one TypeScript package, not a monorepo. The modules form a browser capability that can later be hosted by a desktop agent without making Playwright the domain model.

## Installation boundary

The Codex plugin uses the supported compatibility manifest (`.codex-plugin/plugin.json`, `.mcp.json`, `skills/`). This permits stdio environment-name forwarding and a client timeout longer than the 180-second workflow deadline; the portable MCP schema currently excludes those fields. The repository marketplace is `.claude-plugin/marketplace.json`, a supported catalog location. Codex resolves `cwd: "."` against the installed plugin root; its MCP parser does not interpolate hook-style `${PLUGIN_ROOT}` variables. See [official packaging guidance](https://developers.openai.com/plugins/build/plugins) and [parser implementation](https://github.com/openai/codex/blob/main/codex-rs/codex-mcp/src/plugin_config.rs).

Build stages a small bundle in `dist/plugin/`. Only the manifest, MCP declaration, skill and bootstrap scripts enter the replaceable Codex plugin cache—not `node_modules`, benchmarks, builds or user data. `npm run setup` prepares the retained clone and registers its absolute runtime location in user-owned `~/.ratatoskr/runtime.json` (`RATATOSKR_HOME` override). The bootstrap imports that runtime's compiled server without shell command construction and sets run storage to the user data directory. Moving a clone requires setup again. CLI/bare MCP storage defaults remain unchanged.

Setup neither edits Codex configuration nor saves environment values. `--value-refs` adds only selected variable names to the staged forwarding/allowlist configuration. The skill is operational guidance, not part of the executor, and adds no tools. CLI/MCP versions come from package metadata; distribution checks ensure the plugin version agrees. Doctor probes dependencies and writability; smoke uses a temporary localhost fixture and real stdio MCP client. Neither calls a model. Clean-install tests use a committed fresh clone and isolated browser/runtime/Codex directories.

## Dependency boundaries

```text
CLI ─┐
     ├─> application composition ─> executor ─> BrowserAdapter ─> Playwright adapter
MCP ─┘             │                    │
                   ├─> RunInspector      ├─> evidence collector/reducer
                   └─> stores/resolvers  └─> protocol types
```

`src/protocol.ts` owns Zod schemas and domain records, with no Playwright imports. `src/browser.ts` defines the narrow browser port; only `src/playwright-adapter.ts` imports Playwright. `src/executor.ts` executes validated workflow control flow; it does not interpret goals. `src/evidence.ts` timestamps, redacts, counts, and deterministically reduces evidence. `src/storage.ts` implements run/artifact interfaces on the filesystem. `src/inspection.ts` provides bounded, deterministic run inspection for both transports. `src/application.ts` composes these parts. `src/cli.ts` and `src/mcp/server.ts` are thin input/output adapters. Removing `src/mcp/` does not affect CLI execution or inspection.

## Plan and execution

`BrowserPlan` has an HTTP(S) start URL, up to 300 discriminated steps, optional plan/step timeouts, and optional explicit output names. The shared default workflow deadline is 180 seconds; CLI plans can explicitly override it, while compact MCP plans use the server default. The step cap and default deadline are defined in `src/protocol.ts` and reused by validation/execution to prevent drift. Actions cover navigation, semantic targeting, form controls, hover, bounded uploads/downloads, assertions, and targeted text/attribute extraction. Targets prefer role, label, text, or test ID; CSS is an escape hatch. There is no arbitrary JavaScript, shell, filesystem traversal, looping, or autonomous planning. URL credentials and non-HTTP(S) navigation are rejected.

The executor validates before preparing a run or opening the browser, allocates a unique run ID, starts an isolated browser/context, performs initial navigation, and walks the selected steps in order. Playwright auto-waits for actionability; required assertions wait to a bounded timeout. A failure stops the plan unless that canonical CLI step permits continuation. Each step records timing, status, and URL. A deadline races browser startup and operations, closes the browser on exhaustion, and caps further execution. Session captures and failure/cleanup work have their own diagnostic bounds and can add overhead beyond the execution deadline. MCP cancellation closes the browser best-effort and persists the run as `aborted`. The MCP process permits one active workflow; additional calls receive an explicit tool error.

`valueRef` resolves locally through the value resolver. Only the reference name persists. The MCP adapter restricts names to `RATATOSKR_ALLOWED_VALUE_REFS` (empty by default); the CLI retains its local resolver behavior. An upload accepts a basename inside a configured directory, not an arbitrary plan path. A download is saved through the artifact store; no plan-supplied write path exists. Extraction values are capped, persisted separately, and returned on either success or failure when named in `outputs` and completed before the failure. Unexpected dialogs/popups fail; a click can declare one dialog policy or an expected popup, after which the popup becomes the active page.

### Workflow context and static validation

Compact input passes through `normalizeWirePlan` to the same canonical `BrowserPlanSchema` used by CLI/executor. The guiding MCP schema references one recursive step definition instead of duplicating branches. An iterative structural preflight rejects more than 300 nodes or branch depth two before recursive Zod parsing. Both selected and unselected branches count; there are no loops. A stable preorder index identifies steps across branch choices.

`src/workflow-variables.ts` validates variable dataflow before browser startup. Parameters and extraction saves share a per-run `Map<string,string>`: at most 20 names, regex `^[A-Za-z_][A-Za-z0-9_]{0,63}$`, 1,000 characters per value. Saves are unique across all branches, including mutually exclusive branches. A value needed after a branch must be guaranteed on both paths; `variable_exists` can guard optional values locally. Continued failed extractions do not guarantee a variable. Malformed templates, undefined references, duplicate names and collisions with any used secret `valueRef` are rejected concisely.

Extraction retains the full bounded value for subsequent steps rather than the shortened model output. Each step resolves `${name}` immediately before execution, once only; inserted template-looking data is not recursively evaluated. Allowed fields: navigation `url`, text/URL `contains`, semantic locator `name`/`label`/`text`/`testId`, fill `value`, select value/label. Forbidden: start URL, CSS, role, action, variable/secret reference names, attribute names, key sequences, filenames/paths and configuration. Output fields are capped at 2,048 characters; final navigation must still be credential-free HTTP(S), and targets must still validate. Secret resolution never reads the workflow map. Literal fills remain disallowed; parameters are explicitly non-secret data. Runtime references can fail with `undefined_variable`; invalid/oversized data fails with `invalid_variable`.

Compact `save` returns every explicitly saved value (five outputs, 200 characters each). Canonical plans separate `saveAs` from `outputs` (five, total 2,000 characters), so intermediate saves can remain local. Variable values are never placed in execution trace entries. Known secrets are redacted before persisted extraction/output truncation; unknown secrets remain a documented limitation. There is no input-value extraction action in this milestone; existing text/attribute extraction plus safe CLI parameters cover the target flows.

### Conditions, retry and recovery

Canonical branches use `action:'branch'`, a discriminated `condition`, `then`, optional `else`. Compact branches use `if:'visible'|'url'|'exists'|'equals'`, flat fields and the same child arrays. Canonical predicates are `visible`, `url_contains`, `variable_exists`, `variable_equals`; optional `not` negates the answer. Visibility observes for at most 250 ms; other predicates read current state immediately. Branch errors fail instead of silently choosing an alternative. Use required waits for expected readiness. Only the selected path executes; decisions stay in local step records, not successful results.

`src/workflow-retry.ts` validates policies and classifies retryable failures above Playwright's auto-wait. `retry` is total attempts, integer 1–3. Without a policy, only recognized transient GET-navigation errors (connection reset/closed, network change, timed out network or aborted navigation) get a second attempt; ordinary navigation timeouts do not. Explicit navigation/wait/hover/extraction retries accept timeout, absent element or transient navigation failures. An observed HTTP status >=400 anywhere in the run conservatively vetoes subsequent retry, even if unrelated. Assertions, deterministic browser errors, credentials, mutations, dialog/popup clicks, uploads and downloads are not replayed.

Explicit click retries run Playwright's `trial` actionability check first. Failure before dispatch is `target_not_ready`; after dispatch an exception is `side_effect_state_unknown` and stops replay. Trial readiness cannot prove application-level idempotency, and a successful click followed by a failed assertion does not retry the click. The only recovery is `reloadOnce` on waits/extractions with exactly two attempts. The adapter verifies the last main-frame document request was GET; POST documents are not reloaded. Recovery failure stops. There is no renavigation inference or arbitrary recovery subworkflow. GET requests themselves can have side effects in badly designed applications; Ratatoskr cannot prove server idempotency.

Execution counts initial navigation, selected branch nodes, primitive attempts and recovery reloads toward a hard 360 limit; retries also have a global cap of 60. The overall deadline defaults to 180 seconds (canonical CLI override up to 600 seconds). A startup that finishes after the deadline is closed when it completes. Other retry delays are 250/500 ms, capped by the remaining deadline. Exhaustion returns `budget_exhausted`. Step records retain bounded attempt/retry/recovery/variable-name entries with timestamps; retried initial navigation is stored separately in run metadata and included at index -1 by existing paged `steps` inspection. Successful responses omit branch and retry history. Exhausted failure shows the final classified reason and attempts without repeated Playwright stacks.

### Deterministic test conversion

The CLI lazily imports `src/derive-workflow.ts` and TypeScript's parser; MCP never loads this utility and has no generation tool. `derive-workflow <file> --base-url <HTTP(S)>` reads at most 256 KB, finds at most ten named sequential `test` callbacks, and emits at most 64 KB with up to 25 location/reason warnings per test. It rejects malformed syntax using TypeScript's public in-memory syntax diagnostics rather than trusting parser recovery. It never executes code, imports modules or recursively searches a repository. Existing `rg`/source-reading is sufficient for other metadata; no redundant source-index API is added.

Supported statements have awaited, literal `page.goto`, `getByRole` (literal name), `getByLabel`, `getByText`, `getByTestId`, `.click()` without options, `.fill(process.env.NAME)` with optional non-null assertion, `expect(locator).toBeVisible()` and `.toContainText(literal)`. The first action must be navigation. Later navigations remain steps. Literal `expect(page).toHaveURL` emits a contains assertion with a weaker-semantics warning, keeping `ready:false`; regex is unsupported. Arbitrary variables, loops, hooks/setup, dynamic calls, page objects, CSS/complex locator options, arbitrary assertions and action options are unsupported. Unknown execution stops conversion at a safe sequential prefix; unknown top-level setup marks all tests incomplete. Every emitted plan is passed through the normalizer/canonical validator. Incomplete plans require planner review; CLI exits nonzero when conversion is not fully ready. This is assistance for Codex, not an autonomous planner.

## Evidence and progressive disclosure

The Playwright adapter emits request, HTTP error, request failure, console, page error, navigation, dialog, and popup events. The collector assigns timestamps/step indexes and redacts resolved values before persistence. The reducer ranks errors occurring in the failed step or within two seconds around it, favoring severe and same-step events; it returns at most three. This heuristic is deterministic, but does not establish causality for delayed asynchronous effects. Successful requests are counted, not returned. Network bodies and accessibility snapshots are not captured in this milestone.

Level 0 is a tiny success result (`success`, `runId`, plus only explicitly requested outputs/download IDs). Level 1 is a compact failure with step, reason, useful URL/errors, and artifact IDs. Level 2 uses shared `inspectRun` categories with a default of 10 and hard limit of 25 items per category, 300-character message limits, deterministic order, and truncation metadata. Level 3 explicitly retrieves one registered artifact. MCP screenshots use image content; small text files can be text; traces and large binary downloads return metadata plus a local path rather than inline bytes. The MCP server does not expose a general filesystem resource.

Failure screenshots and safe traces are registered by ID. Tracing is disabled for plans containing fills, uploads, or prompt value references because traces can retain secrets. Screenshots mask form controls and matching resolved text; canvas/image-rendered secrets remain a limitation. The artifact store verifies IDs against its registry before reading. MCP stdout is reserved for protocol traffic; diagnostics go to stderr without resolved values.

## Persistence and measurement

Runs live beneath `RATATOSKR_DATA_DIR` (default `.ratatoskr/`): `runs/<runId>/metadata.json`, `workflow.json`, `steps.json`, `evidence.jsonl`, `extractions.json`, `reduced-result.json`, and `artifacts/`. Artifact metadata is also indexed by ID for MCP lookup. Metrics track step/action/error counts, duration, serialized event bytes, reduced response bytes, artifact count, and compression ratio. These are byte counts, not token counts; binary artifacts and MCP schema overhead are measured separately in integration tests.

The stdio MCP adapter uses the official SDK and exposes exactly three tools. It shares the executor and inspector with CLI, but not the input syntax. `src/mcp/wire-plan.ts` advertises a small flat schema, normalizes `url`/`do` steps and inferred locators into the strict canonical BrowserPlan, and validates that canonical plan before execution. Removing MCP still leaves CLI behavior intact. Future desktop-agent integration should treat this as one capability behind a permission boundary, not as the planner or event bus.

## Model-facing efficiency boundary

SDK input validation passes unknown input to application validation deliberately: the guiding JSON schema describes the compact syntax, while the normalizer owns concise semantic errors. No input reaches the executor without canonical Zod validation. Invalid locators, actions, URLs, output names, and unsupported fields return one bounded repair (under 750 serialized bytes), not union issue arrays. The same protection applies to inspection and artifact arguments. Schemas omit rarely needed timeout, evidence, continuation, and output-list knobs; these remain available internally/through CLI.

MCP extraction `save` requests an output automatically, capped at five identifiers and 200 characters each. Completed requested values survive a later failure (canonical `outputs`, MCP `values`). Text assertion failures can include a best-effort 250 ms reread, redacted before truncation to 200 characters; missing targets have no fabricated actual text. This reduces inspection calls without adding an exploration capability. An unambiguous `has` step with another locator and `text` is normalized as expected text; other ambiguous locators remain invalid.

After a click timeout, the adapter may perform a bounded 150 ms existence probe. An absent target gets an `element_not_found` classification and a redacted, capped reason. Present but disabled/covered controls retain timeout semantics. Probe failure never masks the original failure. This returns neither page content nor suggested replacement targets; it addressed a measured three-call locator diagnosis without adding browser capabilities.

Inspection keeps shared hard bounds (25 items/category, 300-character messages) and MCP defaults to 10 items. Its public API exposes categories and offset, not unbounded dumps or size knobs. Images and trace bytes remain explicit artifact retrieval only.

## Internal session observation

`src/session.ts` contains the Playwright-independent comparison model, allowlist sanitizers, journal and deterministic reducer. The browser port accepts internal observation callbacks and optional snapshot/state methods; none are BrowserPlan operations. The adapter uses `context.cookies()`, `storageState({ indexedDB: false })`, individual `response.headerValues('set-cookie')`, and one fixed read-only active-tab sessionStorage expression. Optional IndexedDB, passkey/credential and OPFS capture remain off. See [context APIs](https://playwright.dev/docs/api/class-browsercontext), [response headers](https://playwright.dev/docs/api/class-response) and [authentication guidance](https://playwright.dev/docs/auth).

Cookie identity includes name/domain/path/partition key. Values are compared with per-run HMAC fingerprints held only in memory; persisted snapshots/deltas omit values, hashes and comparison keys. Metadata and derived expiry are allowlisted and bounded. Storage identity includes area/origin/key; active tabs are not conflated. Storage deltas include a comparison interval and do not claim exact mutation timing. Removed and re-added keys between full captures can be missed.

Complete snapshots bracket the workflow and first failure, with a post-navigation baseline. Lightweight cookies follow navigation, click, press and download boundaries, not every assertion/fill. Each capture has a one-second budget. Responses preserve observation timestamps/step association before asynchronous header access. Non-retention compares the earliest complete snapshot after that response, not a later logout. Findings use the failure's nearby two-second window (with a bounded allowance for failure capture), and prefer decisive missing/removed/value-changed facts over redundant network/storage data. HTTP 401/403 is correlation, not proof of an auth bug; cookie presence means context presence, not proof the request carried it.

The first-failure snapshot is retained for reduction even if CLI continuation later changes state. All observed credential values enter the existing redactor; earlier console events, step failures, extraction values and workflow strings are scrubbed before ordinary persistence. Request `allHeaders()` supplies credential-bearing fields for protection only, never persistence; `headers()` can omit them ([request API](https://playwright.dev/docs/api/class-request#request-all-headers)). Protocol keys/literals are preserved even when a short storage value collides with them; free-form fields are still redacted. Text truncation happens after final redaction to avoid leaking a partial credential. A 16,384-character retention ceiling rejects oversized extraction and omits oversized failure text rather than retaining an unbounded DOM string. Screenshots mask known values. Secret-bearing traces are discarded rather than offering a credential-bearing ZIP as an ordinary artifact. Unknown/canvas/image secrets and incomplete/inaccessible storage remain limitations; this is not a DLP system.

Run storage adds optional sanitized `session.json` and nested volume/timing metrics. Old runs load without that file. `inspectRun` adds one `session` category with shared paging and a 6 KB item cap; nested response cookie lists are capped at three with counts/truncation. A final cookie snapshot timestamp/count/completeness flag supports absence reasoning even when paging selects other items. No cookie schemas or new tools enter MCP input definitions. `rawLocalSessionEvidenceBytes` measures serialized sanitized local metadata, not secret values or the optional full state artifact; `cookieCountObserved` is the peak retained cookie count per run.

Full `browser_storage_state` artifacts are default-off and captured only on relevant failures when `RATATOSKR_CAPTURE_AUTH_STATE=1`. They are stored as `.storage-state.json` with private directory/file modes on supported systems. Type-enforced sensitivity cannot be downgraded by toggling metadata flags. Inline read and CLI export refuse them; MCP returns safe metadata without a path. `FilesystemArtifactStore.readProtectedState` is an explicit local internal capability reserved for possible future reuse. IDs resolve through the registry and realpath checks; no arbitrary plan path is accepted. Existing local users/admins can still read the plaintext file. Generated state is ignored and excluded from packages; there is no automatic retention cleanup.

The session benchmark reuses native Codex launch, accounting and terminal-event measurement. Diagnostics off/on share observer, schemas, source facts, prompt and browser state; only automatic Level 1 differs. The auth direct baseline extends official Playwright MCP with read-only storage lists and request details, without JavaScript/code execution. Every requested group uses fresh tasks, rotates ordering and retains unsuccessful diagnoses. Session evidence bytes and provider-reported tokens remain separate. Counts-only publication verifies native usage and excludes tool bodies/auth state. `RATATOSKR_SESSION_DIAGNOSTICS=off` is not an emulator of the old code: it isolates the Level 1 effect, not snapshot runtime overhead.

## Browser evidence benchmark

`benchmarks/browser-evidence/` is an experimental harness outside the production dependency graph. Its original direct adapter uses individual Playwright actions and uncompressed observations. The token matrix also uses pinned official Playwright MCP with its native discovery metadata, bulk fill and default observations; arbitrary code execution is excluded from this explicitly scoped baseline. The Ratatoskr session spawns the actual compiled MCP server with isolated local storage. The harness does not substitute a custom executor, reducer or inspector. Local fixtures supply identical real persistence, deterministic HTTP 500 or absent-control scenarios to both modes, with shared source facts and fresh browser state.

Offline replay validates browser/evidence behavior without model usage claims. An optional Responses API loop records every provider response's usage. The Codex driver launches a fresh ephemeral CLI task per run, exposing the same benchmark browser sessions over MCP and recording native `turn.completed.usage` totals. It disables unrelated tools/instructions, scopes unattended approval to the fixture server, and never resumes the development conversation. Cached input and reasoning output are subsets, not extra tokens. Missing accounting remains unavailable; exec does not expose per-inference counts. Both model integrations are benchmark-only; production remains a deterministic executor. Summaries use paired configurations, matching accounting sources, medians, and explicit missing metrics. Raw event evidence, local binaries, returned tool payloads, and model token usage are distinct measurements. See the benchmark README for methodology and reproducibility limits. Domain permissions remain future work.

Terminal MCP events, including pre-handler validation and transport failures, account for every model-visible tool reply. Invalid arguments and valid runtime failures have separate counters. Immutable audit files verify native usage, method/path diagnosis and the call budget without replacing original evidence or excluding unsuccessful tasks. Published summaries regenerate from per-run records and are tested against the original native completion events.
